# 分层采集与刷新频率

## 平台页面的采集设置

导航中的“平台健康”已改为“平台”。在本页“设置 · 采集项目与频率”可配置以下全局采集分组；以秒为单位，数字越小采集越频繁。设置存储于 PostgreSQL，保存操作要求来自平台同源 HTTPS 页面，带配置版本的并发校验及审计记录，不写系统配置、不执行 SSH 或改变 Agent 权限。目前仍是内网无登录项目，审计不会伪称已验证管理员身份。

| 项目 | 默认间隔 | 允许范围 |
| --- | --- | --- |
| 实时 CPU / 内存 / 网络 | 1 秒 | 1–60 秒 |
| 完整上报、心跳与 Agent 进程性能 | 10 秒 | 5–30 秒 |
| GPU 核心 / 显存 / 温度 / 功耗 | 10 秒 | 5–3600 秒，且不短于完整上报 |
| 磁盘容量 / I/O | 30 秒 | 10–3600 秒，且不短于完整上报 |
| CPU / SSD 温度 | 30 秒 | 复用磁盘周期，但不短于 30 秒；只读已识别的 hwmon 传感器 |
| 用户、存储拓扑、网络、代理、软件服务、安全、AI 和编程工具扩展清单 | 60 秒 | 30–3600 秒 |
| 目录隔离 / sudo / root 权限审计 | 300 秒 | 60–3600 秒 |
| OS / 内核 / CPU 型号等基础信息 | 300 秒 | 60–86400 秒 |
| 平台 Server 进程性能 | 15 秒 | 5–300 秒 |
| 平台与节点链路检查 | 15 秒 | 5–300 秒，按需检查缓存 |
| Gitea 健康 / 版本 / 账户 | 60 秒 | 30–3600 秒，按需读取缓存 |

扩展清单共用一次扫描，不能将其中的用户或软件工具各自设成独立计时器。慢项目在完整上报周期中检查缓存是否到期，因此实际间隔向上对齐上报周期（允许约 250ms 的调度误差），权限审计使用最近一次用户清单。GPU 失败仍至少退避 60 秒。按需项目只有在页面请求且缓存到期时才重新检查，不承诺后台持续轮询。

设置随成功完整报告的响应下发，Agent 在线热应用，并在下一次报告中回传实际策略；页面列出每个节点的应用版本。未升级 Agent 明确显示“需更新 Agent”，不能把“保存成功”当作所有节点已生效。配置不会触发提权、降权或服务重启。Agent 离线时继续使用最后已应用的内存策略；重新启动后先用安全本地默认值，成功上报后再应用平台持久策略。

GPU、磁盘和轻量指标各自保留真实采集时间；历史曲线用原采样时间去重，不把缓存值伪装为新采样。清单、权限和实时通道的过期判断跟随配置调整；浏览器页面刷新仍独立于采集设置。以下为默认策略的通道说明。

设备总览的 CPU、内存和网络采用独立的 1 秒轻量通道。Agent 只刷新这些基础计数器，通过已有 Agent 令牌认证的 HTTPS `/api/v1/agent/live` 上报；Server 在内存中保留各节点最新值，通过 `/api/v1/nodes/live` 供可见的总览页面每秒读取。实时通道不写入 PostgreSQL，也不携带用户、软件包、设备或代理清单。浏览器仅在当前标签页显示总览时轮询；离开页面或切到后台即停止。前端保留最多 5 分钟的本次浏览器会话实时点，用于补充历史曲线，刷新浏览器后这段细粒度曲线不会恢复。

| 频率 | 内容 | 存储 / 展示 |
| --- | --- | --- |
| 1 秒 | CPU 使用率、内存、网络收发速率 | Server 内存最新值；总览可见时浏览器短时曲线 |
| 约 10 秒 | 完整 Agent 上报，包括 GPU 与基础心跳 | PostgreSQL 最新快照和长期历史；GPU 图沿用实际采样时间 |
| 最多每 30 秒 | 磁盘容量和 I/O | 复用完整上报，不增加磁盘轮询 |
| 约 60 秒 | 用户会话、进程、代理、服务、块设备树与分区位置等扩展信息 | 缓存后随完整上报发送 |
| 最多每 5 分钟 | OS、内核、CPU 型号等节点基础清单 | 缓存后随完整上报发送 |

总览仍每 5 秒读取完整节点快照、每 15 秒读取 PostgreSQL 近 10 分钟历史；实时通道只负责 CPU、内存和网络的秒级变化。GPU 查询保留原来的完整上报频率，失败时退避；磁盘 I/O 保留约 30 秒实际采样。页面明确显示频率，不能把 GPU 或磁盘的旧数值冒充每秒新采样。

实时请求超时或 Agent 断线时，不补零、不伪造变化，页面回退到最近一次完整快照并提示实时通道异常。超过 4 秒未到达的实时值不再由 Server 提供。Agent 使用跳过错过 tick 的调度方式，避免故障时积压每秒任务；实时通道不进入 SQLite 离线队列，恢复连接后只展示新样本。完整报告及离线持久队列保持原样，旧版 Agent 仍可通过原接口上报。Server 重启会清空内存实时值，但数据库历史不受影响。

这样两台节点每天约有 172,800 个轻量实时请求，但不会额外产生 172,800 行数据库历史记录，也不会每秒执行 GPU、磁盘或软件包扫描。生产环境只做部署后的只读健康和实际采样时间核对；故障与负载测试在隔离环境进行。
