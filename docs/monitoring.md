# 监控与权限

## 暂停监控与停止 Agent

机器管理的每台机器操作组分别提供「暂停监控 / 恢复监控」和「停止 Agent」。暂停只停止指标采集与上报，保留 Agent 进程、每分钟轻量控制心跳及 SSH 监控长连接，可直接点恢复；旧版 Agent 未支持暂停时明确显示待更新，不假称已停采。

停止 Agent 是独立的进程操作：先核验原机器 ID、SSH 主机公钥、原 Basic / Full 模式及权限，再停止固定的 `easymanage-agent.service` 或用户兼容守护，禁用开机 / cron 自动拉起，并关闭此节点的 SSH 监控长连接。Basic 使用原 SSH 账户，不执行 sudo；Full 使用独立的管理员保险库授权。安装文件、配置、SQLite 身份与历史、平台历史均保留，不停主机、平台、数据库或其他服务。旧版 Agent 也可由服务管理器完全停止，不依赖其暂停协议。

停止后只有「重新部署 Agent」能继续：恢复监控、普通 / 强制重启、更新、提权和 SSH 网络重连均不能绕过停服状态。重新部署复用原 ID 和权限，恢复监控；其他额外采集开关保持。Full 可分别使用原普通 SSH 账户传输文件和另一个管理员账户恢复系统服务。平台本机 Agent 仅在明确停服后开放此恢复入口，不重新部署平台自身。部署成功仍须新注册凭据、新进程及真实心跳证据；失败或超时显示状态未确认，不假称已恢复。

服务生命周期保存在 schema 21 的 `agent_service_controls`，与采集暂停设置分离。平台重启不重试远端停服副作用，也不自动重连已停止节点；中断操作标为未确认。停服前另在可信清单旁的私有 `agent-service-blocks/<UUID>` 创建无凭据标记，只在新进程重新部署并收到真实心跳后移除；这样 PostgreSQL 故障时原有应急重启仍可用，也不会绕过已停止 Agent 的状态。旧节点没有生命周期记录时保持原行为。服务动作有机器级互斥、版本检查及不含凭据的审计；密码 / 私钥仅存平台密文。仅新增一张按节点主键索引的状态表，不增加监控轮询或周期 SSH 检查。

## 外部算力平台入口

设备总览的「添加机器 → 接入方式」支持外部算力平台，填写名称、完整 HTTP/HTTPS 链接及可选备注即可添加。入口以独立机器卡片展示，提供「前往算力平台」大按钮，在新标签页打开；与受管节点分开计数，不显示虚构的在线状态或监控指标。名称、链接、备注和删除状态保存在 PostgreSQL，支持编辑、软删除及从机器管理恢复，重启和升级后保留。外部入口不受 Agent 候选包、CA 或 SSH 清单是否可用的限制，原 Agent 部署仍核验这些前置条件。

平台仅存储链接，不请求目标网站、不解析目标 DNS、不部署或控制 Agent，也不触发 SSH。只接受有主机名的 HTTP/HTTPS URL，禁止脚本、文件协议及 URL 中的用户名密码；保留合法路径、查询和片段。写入沿用同源 HTTPS 规则和版本冲突检查；审计只记操作和版本，不重复记录链接。入口清单仅在总览按分钟刷新、前台恢复可见和人工修改后读取。迁移 20 仅新增 `external_platforms`；停止平台后可用 `deploy/database/rollback-external-platforms.sql` 恢复迁移 19 兼容性，入口数据保留供再次升级使用。

## 低开销采集与资源评估

各监控页面中的机器详情卡片在整机监控已暂停或暂停待确认时默认收起，仅保留名称、状态、采集时间与管理操作；可独立点击「展开 / 收起」查看历史详情。普通轮询不重置手动展开的选择，新一轮暂停重新默认收起，恢复监控后自动展示详情。仅离线但未暂停的机器保持原展示。收起时不挂载图表、磁盘拓扑或明细表，不改变采集设置、Agent 控制、历史数据或后台任务；机器管理中的恢复入口保持可见。

SSH-only Basic 更新使用随机标记与安装文件 SHA-256 校验完成回执，不依赖脱离进程可能持有的输出 EOF；有效回执才登记版本，并复用已有控制连接。缺失或错误回执仍保留失败状态和恢复文件，不因看见一次心跳就猜测安装摘要。

实时指标和配置中的上报频率保持不变。Linux 网络计数每轮只读一次 `/proc/net/dev`；进程名称复用已经读取的 status，不再逐进程重读 comm。软件包清单缓存一小时，包数据库的修改时间或大小变化时，下轮扩展采集立即刷新；失败最多缓存一分钟。暂停监控仍每分钟保留一次轻量控制，正常监控复用完整上报返回的控制与采集设置。

平台将软件包列表独立保存在 `node_software_inventory`，动态心跳不重写这部分 JSONB；旧版 Agent 的完整上报仍兼容。新版 Agent 在收到服务端明确确认后才使用版本 2 的紧凑上报，清单缓存缺失或平台回退旧版时自动重传版本 1 完整数据，避免把省略清单误认为空清单。SQLite 待发送队列按内容摘要共用软件清单，离线队列中的不同版本仍分别保留，补报不丢失原始数据；同一节点、同一采集时间的重试不再产生重复历史样本。新版平台启动包含数据库迁移 17/18，升级前保留数据库备份；已验证的应急回退脚本为 `deploy/database/rollback-resource-accounting.sql`，必须停止平台后执行，保留原历史并恢复旧版结构，新增加的精确计量列会移除。

每秒 live 通道只缓存已通过 PostgreSQL 校验的凭据摘要，最长十秒、最多 1024 节点；完整上报及控制请求仍查数据库。重新注册、删除或恢复机器会使缓存失效，查询期间发生撤销也不能填回旧缓存；数据库外直接改凭据的可见延迟最多十秒。摘要缓存不保存明文密钥或密码。普通页面只请求轻量节点视图，软件页才加载完整软件清单；未变化的数据用 ETag/304 复用，平台和 Gitea 页面停止无关的全量节点轮询，隐藏标签页不继续后台刷新平台资源。首页十分钟历史仅保留 CPU/GPU/温度字段，不为每个历史点保留整份账户、软件或磁盘清单。

公开节点视图及实时展示资格最多缓存一秒，多个浏览器的并发读取共用一次数据库查询；完整和轻量节点视图分开，已序列化正文及 ETag 直接复用，每项最多 8 MiB，超大结果仍正常返回但不驻留缓存。上报、注册、暂停/恢复、机器增删改及控制确认在事务提交后立即使缓存失效；并发旧读取不能填回失效结果。错误和取消的请求不缓存，数据库外直接修改的可见延迟最多一秒。不缓存 SSH 授权、密码、私钥或管理员操作结果，也不增加部署连接。

资源页区分整机 CPU 百分比与单核百分比（一个核满载 100%，多核可超过 100%），记录实测采样区间；新版 CPU/I/O 历史按区间时长加权，并给出实际覆盖秒数及累计读写，旧数据保留样本均值。缺失、计数回退、首个尚无基线的采样不补成零。RSS 是主进程口径；独立 EasyManage 服务另报 cgroup v2 CPU、总内存和块设备 I/O，包含采集子进程。没有独立服务的 SSH 兼容守护显示未知，不能把整个用户会话计入。服务块 I/O 按设备内核计数汇总，设备映射层可能重复，不冒充物理盘独占吞吐。逻辑读写包括命中缓存及 procfs 等读取，不能与物理磁盘字节或网络字节相加；共用 PostgreSQL/Nginx CPU 仍不冒充本平台独占开销。

最新资源采样显示实际采集时间，按配置频率检查过期；暂停、离线和过期的读数标为历史值，不能因为页面刚刷新或收到旧队列补报就当成当前占用。服务内存按内核 cgroup 记账，RSS 包含进程共享映射，两者不构成包含关系，不可相加。未开放给用户服务的 I/O 控制器显示未知，不为了补一个数值而修改生产 cgroup 控制器或借用整机 I/O。

服务口径依据 [Linux cgroup v2 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)；静态 JSONB 独立保存以避免反复改写大字段，参见 [PostgreSQL TOAST 文档](https://www.postgresql.org/docs/current/storage-toast.html)。Server 默认按可用 CPU 数创建最多 4 个异步工作线程，`EASYMANAGE_SERVER_WORKERS=1..32` 可按实际并发调整；SSH 会话上限与重连策略不变。

网络页每台机器的路由表默认折叠，标题显示路由条数，点击可独立展开；只改变展示，不增加采集或请求。

Security 页的 AppArmor、ASLR、ptrace 和 Kernel Lockdown 配置固定每小时采集一次，独立于扩展清单。Agent 将实际采集时间及结果保存在本地 SQLite，并按运行 UID 隔离缓存；同一身份重启或暂停后恢复时，未到期的结果继续复用。页面显示小时快照及实际时间，旧版 Agent 明确提示需要更新。账户和 SSH 服务状态仍复用原来的扩展清单频率及各机器开关；无需数据库迁移。

存储页默认隐藏可确认的 `/boot`、`/boot/efi`、`/efi` 和明确标注的 EFI/BIOS 启动分区，可用「显示启动分区」恢复。根分区 `/` 不隐藏；分区图保留隐藏分区的实际位置，不把它算成空闲区域。共享同一文件系统的多个挂载点（例如各用户的 `bigdata`）标注「共享容量」，可展开查看入口；各行容量不能相加，也不代表各子目录自身的用量。新版 Agent 根据内核设备号和文件系统内路径识别关系，旧版上报按同设备名匹配。

Linux Agent 在磁盘采集周期读取 `/proc/self/mountinfo`，补充 NFS/CIFS 等网络共享和 autofs 入口。之前 sysinfo 默认过滤这些文件系统，因而 `/nfs` 可能完全不显示。挂载清单仅读本地内核信息、不上传挂载选项；NFS 不属于本机块设备，因此物理磁盘拓扑不为它虚构硬盘。未挂载的普通 `/nfs` 目录不会被当作独立文件系统，网络盘仍不参与「全部本地磁盘」目录扫描。

网络盘容量单独每小时采集一次，首次发现时开始，固定间隔 3600 秒，不随本地磁盘的秒级采集间隔变化。只对已挂载的网络文件系统调用一次 `statvfs`，不枚举或读取业务文件，不主动探测 autofs 入口。同一网络文件系统的重复挂载复用容量。独立 Python3 子进程串行执行，10 秒超时发出终止请求；主监控线程不等待网络文件系统。硬挂载进入内核不可中断等待时，保留子进程句柄并停止启动其他容量查询；私有状态目录中的固定锁文件防止 Agent 重启后叠加阻塞查询，锁文件不得手动删除。暂停监控会取消采集任务。

尝试时间和最后成功结果保存在 Agent SQLite，重启、暂停后恢复不会立即反复查询。缓存按运行 UID 和文件系统身份隔离，挂载变化前后核验，避免将旧容量用于替换后的文件系统。前端单独显示容量采集时间和失败/超时状态，失败保留原值，超过两轮未刷新标记过期；未成功采集过时显示「容量未采集」，不伪装成零或空盘。网络盘 I/O 速率暂未采集。旧 Agent 仍可上报挂载信息，更新后才启用每小时容量采集。

设备总览 CPU 标题在“线程 · Load”左侧显示内核报告均频（GHz）。Linux Agent 每 30 秒最多读取一次有界 `/proc/cpuinfo`，汇总可用逻辑 CPU（含空闲）的 MHz 均值及范围，复用完整上报和页面已有刷新；不增加外部命令、逐核心探测、SSH 会话或前端请求，不调用 sysinfo 的逐核频率刷新。采样时间随缓存保留；过期、离线、旧 Agent 或没有有效 MHz 时显示“均频 —”。频率是内核报告值，不能据其下降判定硬件热降频；该数据只保存在最新快照，不新增历史表或数据库迁移。

设备卡自动按内核报告的物理 CPU package ID、GPU index 去重识别。仅多于一颗物理 CPU / 一张 GPU 时显示对应控制按钮，默认展开全部详情并显示「收起 CPU / GPU」；单个设备不显示展开按钮。两类展开、收起互不影响，手动收起时不渲染各设备图表。核心、超线程和 NUMA 域不算独立 CPU。CPU 型号、逻辑线程和核心数、频率按已有 30 秒 `/proc/cpuinfo` 缓存分组；各插槽利用率直接聚合已有 sysinfo 核心读数，不新增命令、探测、网络轮询或 SQLite/PostgreSQL 历史。只有 coretemp 已明确标出 `Package id` 的温度才映射到对应 CPU；无法确定的设备温度留空，不复用整机最高温度。CPU 独立曲线复用本页面已有 10 分钟、最多 128 份真实快照，按插槽及实际采集时间去重；重新打开页面后逐步积累，不冒充已持久化历史。未上报拓扑或 package ID 缺失时保持未知，旧 Agent 更新后启用自动识别。

## 七天历史使用记录

设备总览每台机器的「历史使用记录」在独立标签页打开，展示含今天的近 7 个自然日及每日曲线、均值和峰值；日期与页面显示的固定 UTC 偏移一致。CPU、主机内存、GPU/显存、磁盘 I/O、网络与温度使用已有完整上报历史，不采集新的指标、不连接目标 SSH，也不启动实时监控页的轮询。每天和 GPU 切换使用同一份结果，不重新查询。

曲线每 10 分钟汇总，均值按有效采样计算，峰值保留原始有效样本中的最大值；每秒实时通道没有入库的读数不包含在内。缓存读数按对应 CPU、GPU、磁盘和传感器的实际时间去重，空白与离线不补零。主机内存显示历史使用字节，不套用当前内存容量；GPU 显存比例使用当次容量。历史 GPU 编号取七天内并集，消失的卡仍可选择；有效 GPU 数忽略采集失败的空报。

`Overheating` 仅在硬件报告因热限制性能时出现，支持七天、单日及单张 GPU 的记录；70°C 只保留原有温度变红规则。NVIDIA 在原有一次 `nvidia-smi` 查询中附带支持/激活原因掩码，只采用 [SW/HW Thermal Slowdown](https://docs.nvidia.com/deploy/nvidia-smi/#clocks-event-reasons)，不把空闲、功耗限制、供电保护或笼统 HW Slowdown 判为过热；旧 CLI 不支持时退回原查询，降频状态为未知。CPU 复用现有温度采集周期，仅读取内核 [thermal_throttle](https://www.kernel.org/doc/html/latest/admin-guide/thermal/intel_thermal_throttle.html) 计数和累计时间的新增量；首读、计数重置及无接口时为未知，不把开机累计事件记到今天。历史表按真实采集时间去重，显示的是“热降频采样数”，不是事件次数或持续时长。旧温度历史不能反推出降频；不支持的 CPU/SSD、旧 Agent 和未采集的时段均不能判为无过热。支持的 GPU 每轮仍执行一次命令；旧 CLI 首次兼容检测最多额外执行一次，此后恢复原查询。不新增采集频率、SSH 会话或 SMART 探测。

历史读取有少量数据库开销，仅手动打开/重新读取时发生。接口单独使用最多 1 条、空闲 2 分钟释放的只读数据库连接，不占监控上报连接池；按机器/时间索引流式读取，每次最多 250,000 条已有上报及 64 个历史 GPU 编号，超过预算返回明确错误，不静默截断。单并发、不排队，数据库查询超时 5 秒、全流程 10 秒；结果以序列化 JSON 缓存 5 分钟、最多 8 份。无周期聚合或历史页自动刷新，不新增表、索引或 Agent 采集开销。

## 磁盘空间分析

扫描结果会占用 PostgreSQL 数据及索引空间。平台在开始前和扫描中每 2 秒检查结果存储分区：可用空间低于 2 GiB 时拒绝新任务，并通知正在运行的扫描器正常收尾，保留不完整快照。这是存储保护，不是时间或文件数量上限。`EASYMANAGE_DISK_SCAN_STORAGE_PATH` 指定平台可访问的 PostgreSQL 数据文件系统路径，默认 `/`；例如本机数据库可设置为 `/var/lib/postgresql/18/main`。需选择实际承载数据库的文件系统；远程数据库无法通过本机路径测量时应配合数据库服务器的容量监控，此保护不保证远程磁盘空间。检查失败也会停止扫描。数据库另行返回 SQLSTATE `53100` 时明确提示存储已耗尽；既有已写入条目不删除，但缺少最终汇总的失败任务不能当作完整快照展示。不要通过删除 PostgreSQL 文件释放空间，扩容或迁移数据库应另行安排。

存储页最下方的「磁盘空间分析」提供类似 TreeSize 的目录树、逐层占用排序、占上一层百分比、面包屑导航及面积对应大小的矩形图。可在实际分配块占用与文件逻辑大小之间切换，展开子目录、筛选当前展开项，并将当前目录设为下一次扫描范围。图中最多展示 40 项，其余合并；表格分批显示，避免大量目录项阻塞页面。

选择机器和目录后手动开始扫描。普通用户使用可信运维清单中的原 SSH 账户及其实际访问权限；root 级别仅对在线且真实报告 Full / UID 0 的 Agent 开放，并使用平台现有管理员凭据授权。普通用户和 root 扫描的历史、进度、目录汇总及分页结果均沿用平台监控页的访问范围，所有能够访问平台的用户都可以查看，无需管理员凭据。启动或取消 root 扫描仍需同一机器的管理员授权；结果读取不授予 root 执行权限。目录名称和大小属于平台公开的监控信息。

「扫描范围 → 指定磁盘」按当前机器已挂载的本地分区或文件系统选择，显示设备、挂载点和容量。重复绑定入口合并，独立子卷保留；启动分区跟随页面显隐设置，子目录挂载明确提示实际范围。选定后从挂载点执行单文件系统扫描，沿用普通用户/root 权限；不会挂载未挂载分区，也不扫描网络盘或虚拟文件系统。

「扫描范围 → 全部本地磁盘」一次发现并依次扫描所有已挂载、受支持的本地文件系统。结果先按各文件系统的真实挂载路径分组，再展示目录层级和全机汇总；不把挂载路径拼成虚构目录。根据设备号、文件系统和 mount root 去重，`/home/用户/bigdata` 等绑定入口不重复统计；若主挂载点不可读，则尝试可读的绑定子树，并明确标记不完整。不同文件系统共用一次任务的时间、条目预算、取消信号和硬链接去重。网络盘、自动挂载、系统虚拟文件系统及未挂载分区不扫描，也不自动挂载磁盘。全机模式会增加 I/O 与快照存储，需手动启动。

扫描由平台发送固定只读程序，SSH-only 节点复用原控制连接和三连接预算，不新增 Agent 后台采集周期、不改变 Agent 服务。每台机器最多一个扫描，平台最多同时两台；**时间和条目数默认无限制**，API 使用 `seconds: 0, max_entries: 0` 表示不限，也可主动选择有限预算。无限制扫描没有总运行时间、CPU 时间或累计输出字节上限，仍可手动取消；平台重启会中断扫描，需要重新发起。保留 64 层和 256 MiB 地址空间保护，使用低 CPU / 空闲 I/O 优先级，并在遍历中让出时间。扫描只读取目录和 stat 元数据；不读取业务文件内容、解压缩文件、删除文件、修改权限或挂载磁盘。目标需 Python3、util-linux `ionice`；有限时限另需 coreutils `timeout`。

扫描在内存中按目录汇总文件的大小与数量，普通文件元数据处理后立即释放；仅保存目录汇总，不保存逐文件名称或明细。运行中只需保留当前目录栈、最多 256 条待发送目录记录和多硬链接文件的 inode 去重集合，不创建临时 SQLite 文件。硬链接集合也受现有 256 MiB 进程内存保护约束；内存不足会停止并标记不完整。目录汇总分批保存到 PostgreSQL `disk_space_directories`，只维护主键和父目录查找两个索引。页面每次读取 250 个子目录，排序和搜索覆盖全部子目录；“本层文件及目录自身”单独展示直接文件、符号链接与目录元数据占用，剩余子目录另行合并，文件占用不会漏计。时间和文件数量不限，目录批次与分页不截断结果。

迁移 0016 会保留旧版可用快照的目录 ID、大小、数量、层级、时间和权限，转换旧 JSON 快照；删除逐文件历史明细及没有最终汇总的失败任务明细，但保留任务记录。以新目录表替换旧表，提交时直接归还旧数据表和四个索引的磁盘空间，不仅执行 DELETE，也不对整个业务数据库执行 VACUUM FULL。升级前必须备份到独立数据盘并暂停平台写入；迁移不可无损降级到逐文件历史。历史指标、机器身份、监控设置、凭据和 Agent 数据库不在清理范围。

不跟随任何路径分量的符号链接；目录按已打开的文件描述符遍历并检查设备及挂载 ID，每个文件系统内部跳过其他挂载点（包括同设备 bind mount）；全机模式在独立分组扫描其余本地文件系统。仅支持已挂载本地磁盘文件系统；网络、自动挂载、proc/sysfs/tmpfs 等不会扫描。访问失败、取消或触及限制会显示不完整快照：大小是已读取部分的下限，百分比只对应已扫描部分。可缩小目录继续扫描。硬链接只在首次遇到时计数，跨目录分摊与遍历顺序有关；共享块、压缩、快照、文件系统元数据及已删除但仍打开的文件会导致结果与 `df` 不一致。目录同时变化时也不是文件系统一致性快照。

进度每约两秒更新；关闭页面不取消任务。取消会保留已扫描结果；平台重启将运行中任务标为中断，不自动恢复扫描。快照保存在 PostgreSQL 专用表，每机器每级别最近 3 次、最长 7 天、全平台最多 30 个已完成快照；不写入 Agent 身份库或历史指标表。页面只在任务运行时轮询进度，新快照的目录明细按需分页加载。

设计参考完整 [gdu 仓库](https://github.com/dundee/gdu/tree/b723b703fe3b756a9d1422e37495d68d0eb2a4b6) 的层级浏览、实际/逻辑大小与硬链接处理，以及 [dua](https://github.com/Byron/dua-cli) 的占用导航。此实现为独立的流式扫描器与原生 React 视图；运行时无需下载或执行第三方分析工具。

设备总览每台节点的「设备详情」展示处理器、主板、内存条、显卡、显示器、磁盘、声卡及物理网卡。Agent 首次采集后每 86400 秒更新一次，缓存写入自身 SQLite，普通重启复用未到期的缓存；Basic/Full 权限变化时重新采集。打开详情只显示缓存，不触发探测。详情有独立采集时间，离线或超过一天的内容标为历史快照，旧版 Agent 显示待更新。

硬件详情仅限读取内核提供的 sysfs、proc、SMBIOS/EDID，以及现有 GPU/磁盘清单；不运行硬件扫描程序或访问 `/dev/mem`，不导出设备序列号、UUID 和资产标签。DMI 内存条信息不可读时仍显示系统可用物理总量并提示原因；内存数据速率使用 MT/s，显示器尺寸由有效 EDID 得到，未检测到显示器不会伪造型号。SMBIOS 字段与 [Type 17 解码结构](https://docs.rs/dmidecode/latest/src/dmidecode/structures/017_memory_device.rs.html)核对，显示器字段与 [Linux DRM EDID 定义](https://github.com/torvalds/linux/blob/master/include/drm/drm_edid.h)核对。

普通用户 的 Agent 是 Basic，能上报心跳和可读指标，但可能无法查看其他用户的监听端口、进程、目录或受限设备。系统级 Agent 是 Full；页面提权需管理员凭据，仅以新心跳实际报告 UID 0 确认。更新不能自动降权。

用户状态页分别显示终端 utmp 记录、systemd-logind 会话和同一次进程扫描中发现的用户 SSH 进程数量；不会额外扫描。来源可能重叠，因此“至少”数量是各来源数量的下界，不直接相加为准确登录人数。VS Code Remote-SSH 等非交互连接可能通过 logind 或 SSH 进程被发现；未检测到证据不能证明用户已退出，普通 Agent 权限下某些来源可能显示未知。账户「状态」中“正常”只表示登录 Shell 存在且可执行；不读取 shadow，也不声称验证了密码、SSH 密钥或访问策略。`admin` 标记依据可见的 sudo、wheel、lab-admins 组成员资格，root 单独标记。

设备总览每节点一行五图：CPU、内存、GPU 核心/显存双曲线、磁盘 IO 读写双曲线、网络收发双曲线。CPU、内存和网络叠加浏览器可见期间的每秒真实采样，长期底图读取 PostgreSQL 中近 10 分钟的完整上报；没有采样的时间段留空。多块 GPU 的核心曲线取有效设备平均值、显存曲线取总已用量 / 总容量，当前无 GPU 数据时不补零。磁盘 IO 复用 Agent 现有的约 30 秒采集结果，同名设备多个挂载点只计一次，并按磁盘实际采集时间去重；首次没有速率基线时显示为空，不补零或伪装成每秒采样。磁盘容量仍只在「存储状态」页查看。旧版 Agent 若未上报磁盘采集时间，磁盘历史曲线留空。

存储状态页在原有已挂载文件系统表之外，以只读 `lsblk` 和 sysfs 分区起点展示物理磁盘、分区、文件系统及挂载关系，包括未挂载分区。分区条按可读取的真实位置和容量绘制；若位置不可读取，只按容量排列并明确标注。已挂载且可与分区设备路径匹配的文件系统，按已用字节数在该分区内叠加斜线；未挂载或无法匹配的分区保持纯色，不代表其空间未使用。空白区域仅是未被已识别分区覆盖的估算值，可能是对齐或保留空间，不能直接视为可分配空间。采集不读取设备内容、UUID 或序列号，不执行分区、格式化、扩容或挂载命令；页面没有写入操作。

设备总览、各张 GPU 详情和七天历史的 CPU、GPU、磁盘 IO 图叠加温度曲线，独立右轴固定为 **30–95°C**。不超过 70°C 为蓝色，超过 70°C 的部分为普通红线；只有超过 95°C 的部分在顶边显示更醒目的鲜红色特粗线，数值也使用该颜色；浅色主题采用深红色以保持对比度。边界交点按真实温度线性计算后投影到固定坐标，数值仍保留实际温度，不截成 95°C，也不把整条曲线都加粗。图形颜色不等同于硬件热降频的 `Overheating` 提示。左轴仍是使用率或 IO 速率，内存和网络不展示无关温度。CPU 取已识别 CPU 传感器的最高读数，GPU 取有效设备最高温度，磁盘仅取可确认 SSD 的最高温度。SSD 温度提示列出各设备读数。CPU / SSD 只读现有 hwmon 属性，支持 coretemp、k10temp / zenpower 的 Tdie / CCD、NVMe composite 和可确认非旋转盘的 drivetemp；不加载驱动、不执行 sensors-detect / SMART 扫描、不读取机械盘温度、不更改设备。周期复用磁盘设置且不低于 30 秒，GPU 温度复用已有查询。传感器缺失、不可读或旧版 Agent 未上报时显示“温度 —”，不伪造零；历史按真实温度采集时间去重，不将缓存值伪装成每秒新采样。

存储页面的物理机械盘按已核对的厂商型号显示“SMR 叠瓦盘”（橙色）或“CMR 非叠瓦盘”（绿色），点击标签查看匹配型号、资料日期及原始厂商链接。2026-09-29 核对：[Seagate BarraCuda DS1900.14 第 2 页](https://www.seagate.com/www-content/datasheets/pdfs/3-5-barracudaDS1900-14-2007US-en_US.pdf) 明确将 ST2000DM005、ST4000DM004 标为 SMR；[Seagate Exos 7E8 DS1957.1](https://www.seagate.com/content/dam/seagate/migrated-assets/www-content/datasheets/pdfs/exos-7-e8-data-sheet-DS1957-1-1709US-en_US.pdf) 第 1 页说明 CMR、第 2 页列出 ST4000NM0035。匹配允许 lsblk 提供的型号尾缀，不按容量、转速、缓存或系列名称泛化；未收录型号显示“记录方式未确认”。SSD 不属于磁记录分类，不标成 CMR。该标签说明设计技术，不代表磁盘故障或测得了写入性能；不增加 Agent 查询、不访问磁盘数据、不运行写入测速或 SMART 自检。

可见的设备总览每秒读取 CPU、内存和网络实时值，每 5 秒刷新完整节点状态、每 15 秒读取数据库历史；其他页面每 30 秒刷新，后台标签页暂停轮询。实时通道只保存在 Server 内存和当前浏览器短时曲线，不将完整 JSON 报告或长期历史改为每秒写入。详细边界见[分层采集说明](/collection-frequency-design)。

控制台中的 Security 展示节点的安全配置快照；「平台健康」单独展示控制端、数据库和平台与节点的可观测链路。Global Network 监控可见代理进程及监听，不主动验证跨境出口。

「权限检查」是独立的只读页面，按[服务器管理操作手册](/)核对 `/home/用户名`、`/data/shared`、`/data/projects/*` 顶层目录、`/data/scratch`、`/data/archive`，以及 `/root`、`/etc/shadow`、`/etc/sudoers`、`/etc/sudoers.d` 和 `lab-admins` 规则。对 sudoers 可见文件另做 `NOPASSWD:` 字面检查，对 UID 0 别名及 root SSH 目录做特别检查；这不能替代完整 sudo 策略解析。项目目录的组 rwx、setgid、其他用户无权限是基于隔离目标的检查基准，操作手册未规定精确 chmod。Agent 每约 5 分钟采集一次，不执行 chmod/chown、sudo 授权测试或用户身份切换。共享/项目目录 ACL 由限时、限量的 `getfacl` 读取；命令不可用或权限不足时显示未知。最多检查 64 个个人目录、32 个项目顶层子项和 64 个 sudo 附加规则文件，超过上限明确标记截断。检查不递归，不能证明内部文件、NSS/LDAP、所有 sudo include 或实际用户访问能力都符合规范；仅当列明条件可证实时才显示符合。Server 与 Agent 都需要升级到支持该字段的版本；旧版任一组件丢失审计字段时页面显示待更新，不伪造通过结果。

「平台健康」的性能分析按滚动过去 24 小时展示 EasyManage Server 和每个已注册 Agent 进程的 CPU、RSS、磁盘读写速率的有效样本均值与最大值，并显示样本数及首末采集时间。Server 通过独立于页面访问的约 15 秒后台采样持续写入 PostgreSQL；因此平台健康页面的服务端处理开销也计入整个 Server 进程。Agent 进程指标复用完整报告周期并随已有指标样本保存，不增加 Agent 的采集频率。迁移以前的历史无法还原，功能启用后的首个 24 小时按实际已采到的区间显示，不补零、不声称已覆盖整天。旧版 Agent 不上报进程指标时，该节点显示缺少样本。这里是**进程本身**的占用，不把整机 CPU / 内存、共享 PostgreSQL / Nginx 的负载或无法可靠按进程归因的网络开销算进 EasyManage 进程。平台进程采样与其他指标一样按保留期清理。

同一性能表的「存储占用」使用独立的约 1 小时采样与 24 小时均值/最大值，不复用进程 I/O 速率。Server 只读统计自身可执行文件、配置的网页目录（最多检查 10,000 个条目且不跟随软链接）及专用 PostgreSQL 数据库的 `pg_database_size`；Agent 只读统计自身可执行文件和本机 SQLite 状态数据库的主文件、WAL、SHM。文件大小为逻辑长度，未计入共享 PostgreSQL 集群 WAL、Nginx、systemd journal、业务目录及文件系统元数据；采集失败或旧版 Agent 不上报时显示未知，不补零。Agent 每次完整上报可以携带缓存值，但 Server 以真实采集时间去重，不会将 10 秒心跳伪装成新的存储采样。此功能只读文件元数据，不遍历整盘或打开数据库内容。

「网络状态」区分物理有线和 Wi-Fi 网卡；Tailscale 健康读取 `tailscale status --json --peers=false` 的本机状态与健康警告，ZeroTier 健康读取 `zerotier-cli -j info` 和 `zerotier-cli -j listnetworks` 的节点在线、TCP 回退及逐网络授权状态。仅网卡存在或 `up` 不代表组网健康；CLI 未安装、普通 Agent 无权读取或命令失败时显示未安装 / 无法判定，不推断健康。状态随扩展清单约每 60 秒更新；未主动探测两节点间可达性。普通用户常无法读取 ZeroTier CLI 的鉴权令牌，需显式 Full 权限才能获得完整状态，不自动提权或读取令牌。

组网服务卡片各自提供「展开 / 收起」，默认收起；展开显示本机虚拟网络 IP/前缀、接口、入网状态以及 ZeroTier 网络名称和 ID。ZeroTier 按网络对应的准确接口匹配地址，多网络的 IP 不混用；CLI 状态未知时仍可展示内核已上报的虚拟网卡，但不据此推断已入网。真实 VLAN Tag、MTU 和主接口仅在已上报时展示，不将 ZeroTier 网络 ID 冒充 VLAN Tag。离线或过期清单标注历史快照，缺少地址显示未上报。只读取当前页面已有快照，不新增命令、请求、SSH、扫描或采集周期。

AI 工具页面专指 Claude Code、Codex、Gemini CLI、OpenCode、Aider 这类 Agent 工具，不统计推理运行时、模型提供方或 WebUI；编程语言与 GPU 工具仍在编程环境页。新 Agent 仅采集 Agent 工具，前端也过滤旧 Agent 的混合清单，计数与表格范围一致。两类页面只检查固定范围的可执行文件、进程或软件包记录，不执行工具，也不读取配置、环境变量、登录状态、订阅或密钥。命令存在不证明功能可用；缺失也不证明未安装。

AI 安装清单按扩展清单周期后台更新，使用账户清单中的 `/home/<账户>` 与 `/root`，而非仅 Agent 用户目录。支持本地 bin、npm、Bun、OpenCode、pnpm、NVM/FNM/mise、Conda、pipx/uv 的常见安装位置；不递归扫描项目或整个磁盘。Basic 只报告可读证据，Full 也不读取工具配置或用户秘密。每次最多 64 个去重账户目录、1024 个探测目录、单个版本根 128 条目录项/16 个环境及每工具 32 条路径；2 秒工作预算只限制后续探测，不是文件系统调用的硬超时。权限、读取失败或达到上限会显示“扫描不完整”和具体采集限制。Python/Node 等通用进程仍不猜测为 AI 工具；自定义安装位置、服务名和任意项目虚拟环境可能未覆盖。

生产环境中的账户增删改、Agent 提权和网页终端命令会改变目标主机状态，应在明确权限与影响后操作。运行时与故障测试只在隔离环境进行。
