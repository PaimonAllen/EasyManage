# 监控与权限

设备总览每台节点的「设备详情」展示处理器、主板、内存条、显卡、显示器、磁盘、声卡及物理网卡。Agent 首次采集后每 86400 秒更新一次，缓存写入自身 SQLite，普通重启复用未到期的缓存；Basic/Full 权限变化时重新采集。打开详情只显示缓存，不触发探测。详情有独立采集时间，离线或超过一天的内容标为历史快照，旧版 Agent 显示待更新。

硬件详情仅限读取内核提供的 sysfs、proc、SMBIOS/EDID，以及现有 GPU/磁盘清单；不运行硬件扫描程序或访问 `/dev/mem`，不导出设备序列号、UUID 和资产标签。DMI 内存条信息不可读时仍显示系统可用物理总量并提示原因；内存数据速率使用 MT/s，显示器尺寸由有效 EDID 得到，未检测到显示器不会伪造型号。SMBIOS 字段与 [Type 17 解码结构](https://docs.rs/dmidecode/latest/src/dmidecode/structures/017_memory_device.rs.html)核对，显示器字段与 [Linux DRM EDID 定义](https://github.com/torvalds/linux/blob/master/include/drm/drm_edid.h)核对。

普通用户 的 Agent 是 Basic，能上报心跳和可读指标，但可能无法查看其他用户的监听端口、进程、目录或受限设备。系统级 Agent 是 Full；页面提权需管理员凭据，仅以新心跳实际报告 UID 0 确认。更新不能自动降权。

用户状态页分别显示终端 utmp 记录、systemd-logind 会话和同一次进程扫描中发现的用户 SSH 进程数量；不会额外扫描。来源可能重叠，因此“至少”数量是各来源数量的下界，不直接相加为准确登录人数。VS Code Remote-SSH 等非交互连接可能通过 logind 或 SSH 进程被发现；未检测到证据不能证明用户已退出，普通 Agent 权限下某些来源可能显示未知。账户「状态」中“正常”只表示登录 Shell 存在且可执行；不读取 shadow，也不声称验证了密码、SSH 密钥或访问策略。`admin` 标记依据可见的 sudo、wheel、lab-admins 组成员资格，root 单独标记。

设备总览每节点一行五图：CPU、内存、GPU 核心/显存双曲线、磁盘 IO 读写双曲线、网络收发双曲线。CPU、内存和网络叠加浏览器可见期间的每秒真实采样，长期底图读取 PostgreSQL 中近 10 分钟的完整上报；没有采样的时间段留空。多块 GPU 的核心曲线取有效设备平均值、显存曲线取总已用量 / 总容量，当前无 GPU 数据时不补零。磁盘 IO 复用 Agent 现有的约 30 秒采集结果，同名设备多个挂载点只计一次，并按磁盘实际采集时间去重；首次没有速率基线时显示为空，不补零或伪装成每秒采样。磁盘容量仍只在「存储状态」页查看。旧版 Agent 若未上报磁盘采集时间，磁盘历史曲线留空。

存储状态页在原有已挂载文件系统表之外，以只读 `lsblk` 和 sysfs 分区起点展示物理磁盘、分区、文件系统及挂载关系，包括未挂载分区。分区条按可读取的真实位置和容量绘制；若位置不可读取，只按容量排列并明确标注。已挂载且可与分区设备路径匹配的文件系统，按已用字节数在该分区内叠加斜线；未挂载或无法匹配的分区保持纯色，不代表其空间未使用。空白区域仅是未被已识别分区覆盖的估算值，可能是对齐或保留空间，不能直接视为可分配空间。采集不读取设备内容、UUID 或序列号，不执行分区、格式化、扩容或挂载命令；页面没有写入操作。

设备总览的 CPU、GPU、磁盘 IO 图叠加蓝色温度曲线，右轴使用独立的动态 °C 刻度：上下限按当前 10 分钟窗口内的有效读数调整，预留约 2°C 边距并取整，最小跨度 10°C；没有有效读数时上下限显示“—”，不固定为 0–150°C。左轴仍是使用率或 IO 速率，内存和网络不展示无关温度。CPU 取已识别 CPU 传感器的最高读数，GPU 取有效设备最高温度，磁盘仅取可确认 SSD 的最高温度。SSD 温度提示列出各设备读数；蓝色表示温度曲线，不代表已触发过热报警。CPU / SSD 只读现有 hwmon 属性，支持 coretemp、k10temp / zenpower 的 Tdie / CCD、NVMe composite 和可确认非旋转盘的 drivetemp；不加载驱动、不执行 sensors-detect / SMART 扫描、不读取机械盘温度、不更改设备。周期复用磁盘设置且不低于 30 秒，GPU 温度复用已有查询。传感器缺失、不可读或旧版 Agent 未上报时显示“温度 —”，不伪造零；历史按真实温度采集时间去重，不将缓存值伪装成每秒新采样。

存储页面的物理机械盘按已核对的厂商型号显示“SMR 叠瓦盘”（橙色）或“CMR 非叠瓦盘”（绿色），点击标签查看匹配型号、资料日期及原始厂商链接。2026-09-29 核对：[Seagate BarraCuda DS1900.14 第 2 页](https://www.seagate.com/www-content/datasheets/pdfs/3-5-barracudaDS1900-14-2007US-en_US.pdf) 明确将 ST2000DM005、ST4000DM004 标为 SMR；[Seagate Exos 7E8 DS1957.1](https://www.seagate.com/content/dam/seagate/migrated-assets/www-content/datasheets/pdfs/exos-7-e8-data-sheet-DS1957-1-1709US-en_US.pdf) 第 1 页说明 CMR、第 2 页列出 ST4000NM0035。匹配允许 lsblk 提供的型号尾缀，不按容量、转速、缓存或系列名称泛化；未收录型号显示“记录方式未确认”。SSD 不属于磁记录分类，不标成 CMR。该标签说明设计技术，不代表磁盘故障或测得了写入性能；不增加 Agent 查询、不访问磁盘数据、不运行写入测速或 SMART 自检。

可见的设备总览每秒读取 CPU、内存和网络实时值，每 5 秒刷新完整节点状态、每 15 秒读取数据库历史；其他页面每 30 秒刷新，后台标签页暂停轮询。实时通道只保存在 Server 内存和当前浏览器短时曲线，不将完整 JSON 报告或长期历史改为每秒写入。详细边界见[分层采集说明](/collection-frequency-design)。

控制台中的 Security 展示节点的安全配置快照；「平台健康」单独展示控制端、数据库和平台与节点的可观测链路。Global Network 监控可见代理进程及监听，不主动验证跨境出口。

「权限检查」是独立的只读页面，按[服务器管理操作手册](/)核对 `/home/用户名`、`/data/shared`、`/data/projects/*` 顶层目录、`/data/scratch`、`/data/archive`，以及 `/root`、`/etc/shadow`、`/etc/sudoers`、`/etc/sudoers.d` 和 `lab-admins` 规则。对 sudoers 可见文件另做 `NOPASSWD:` 字面检查，对 UID 0 别名及 root SSH 目录做特别检查；这不能替代完整 sudo 策略解析。项目目录的组 rwx、setgid、其他用户无权限是基于隔离目标的检查基准，操作手册未规定精确 chmod。Agent 每约 5 分钟采集一次，不执行 chmod/chown、sudo 授权测试或用户身份切换。共享/项目目录 ACL 由限时、限量的 `getfacl` 读取；命令不可用或权限不足时显示未知。最多检查 64 个个人目录、32 个项目顶层子项和 64 个 sudo 附加规则文件，超过上限明确标记截断。检查不递归，不能证明内部文件、NSS/LDAP、所有 sudo include 或实际用户访问能力都符合规范；仅当列明条件可证实时才显示符合。Server 与 Agent 都需要升级到支持该字段的版本；旧版任一组件丢失审计字段时页面显示待更新，不伪造通过结果。

「平台健康」的性能分析按滚动过去 24 小时展示 EasyManage Server 和每个已注册 Agent 进程的 CPU、RSS、磁盘读写速率的有效样本均值与最大值，并显示样本数及首末采集时间。Server 通过独立于页面访问的约 15 秒后台采样持续写入 PostgreSQL；因此平台健康页面的服务端处理开销也计入整个 Server 进程。Agent 进程指标复用完整报告周期并随已有指标样本保存，不增加 Agent 的采集频率。迁移以前的历史无法还原，功能启用后的首个 24 小时按实际已采到的区间显示，不补零、不声称已覆盖整天。旧版 Agent 不上报进程指标时，该节点显示缺少样本。这里是**进程本身**的占用，不把整机 CPU / 内存、共享 PostgreSQL / Nginx 的负载或无法可靠按进程归因的网络开销算进 EasyManage 进程。平台进程采样与其他指标一样按保留期清理。

同一性能表的「存储占用」使用独立的约 1 小时采样与 24 小时均值/最大值，不复用进程 I/O 速率。Server 只读统计自身可执行文件、配置的网页目录（最多检查 10,000 个条目且不跟随软链接）及专用 PostgreSQL 数据库的 `pg_database_size`；Agent 只读统计自身可执行文件和本机 SQLite 状态数据库的主文件、WAL、SHM。文件大小为逻辑长度，未计入共享 PostgreSQL 集群 WAL、Nginx、systemd journal、业务目录及文件系统元数据；采集失败或旧版 Agent 不上报时显示未知，不补零。Agent 每次完整上报可以携带缓存值，但 Server 以真实采集时间去重，不会将 10 秒心跳伪装成新的存储采样。此功能只读文件元数据，不遍历整盘或打开数据库内容。

「网络状态」区分物理有线和 Wi-Fi 网卡；Tailscale 健康读取 `tailscale status --json --peers=false` 的本机状态与健康警告，ZeroTier 健康读取 `zerotier-cli -j info` 和 `zerotier-cli -j listnetworks` 的节点在线、TCP 回退及逐网络授权状态。仅网卡存在或 `up` 不代表组网健康；CLI 未安装、普通 Agent 无权读取或命令失败时显示未安装 / 无法判定，不推断健康。状态随扩展清单约每 60 秒更新；未主动探测两节点间可达性。普通用户常无法读取 ZeroTier CLI 的鉴权令牌，需显式 Full 权限才能获得完整状态，不自动提权或读取令牌。

AI 工具页面专指 Claude Code、Codex、Gemini CLI、OpenCode、Aider 这类 Agent 工具，不统计推理运行时、模型提供方或 WebUI；编程语言与 GPU 工具仍在编程环境页。新 Agent 仅采集 Agent 工具，前端也过滤旧 Agent 的混合清单，计数与表格范围一致。两类页面只检查固定范围的可执行文件、进程或软件包记录，不执行工具，也不读取配置、环境变量、登录状态、订阅或密钥。命令存在不证明功能可用；缺失也不证明未安装。

AI 安装清单按扩展清单周期后台更新，使用账户清单中的 `/home/<账户>` 与 `/root`，而非仅 Agent 用户目录。支持本地 bin、npm、Bun、OpenCode、pnpm、NVM/FNM/mise、Conda、pipx/uv 的常见安装位置；不递归扫描项目或整个磁盘。Basic 只报告可读证据，Full 也不读取工具配置或用户秘密。每次最多 64 个去重账户目录、1024 个探测目录、单个版本根 128 条目录项/16 个环境及每工具 32 条路径；2 秒工作预算只限制后续探测，不是文件系统调用的硬超时。权限、读取失败或达到上限会显示“扫描不完整”和具体采集限制。Python/Node 等通用进程仍不猜测为 AI 工具；自定义安装位置、服务名和任意项目虚拟环境可能未覆盖。

生产环境中的账户增删改、Agent 提权和网页终端命令会改变目标主机状态，应在明确权限与影响后操作。运行时与故障测试只在隔离环境进行。
