# 平台结构

EasyManage 由 Rust 控制端、Rust Agent、PostgreSQL、Agent 本地 SQLite 队列和 React 控制台组成。服务器 1 同时运行控制端和本机 Agent；服务器 2 运行 Agent，平台通过可信 SSH 清单进行普通用户部署。

| 部分 | 作用 |
| --- | --- |
| `server/` | HTTPS API、节点注册、指标持久化、健康检查和经管理员认证的运维操作。 |
| `agent/` | 定时采集可见的主机指标，断线时将报告保存在本地 SQLite 队列。 |
| `protocol/` | Server 与 Agent 共享的版本化数据结构。 |
| `web/` | 设备总览、用户、存储、网络、安全、代理、AI 工具与编程环境页面。 |
| `docs/` | VitePress 文档源文件，构建后由控制端在 `/guide/` 提供。 |

`/api/v1/nodes` 返回最近一次 Agent 上报的数据；`/api/v1/nodes/{node_id}/history` 返回该节点近 10 分钟的有限历史采样。页面会标出采集时间与历史快照；“未观测到”不等于系统中不存在。

Agent 管理中的「应急重启」提供强制重启平台及逐节点强制重启 Agent。首次验证可信目标的管理员 SSH 与 sudo 后，可复用平台加密保存的密码或私钥，无须反复输入；更换浏览器、授权过期或清除时重新验证。操作会立即结束所选服务的全部进程再启动，当前连接会中断。Full 系统服务即使离线或启动失败，也保留 root 配置。平台重启安排在独立的 systemd 任务中，页面收到接受提示后等待约 5 秒再刷新。请求和结果写入平台服务日志，不记录密码或私钥。详见[管理员凭据复用](./deployment.md#管理员凭据复用)。

数据库不可用时，HTTPS 页面、可信目标清单及应急重启接口仍可访问；监控接口返回 503。平台在后台重试数据库初始化，数据库恢复后自动加载原有采集设置，随后恢复监控。强制重启平台不会自动修复 PostgreSQL；需管理员核对数据库服务、磁盘空间和日志。如果平台进程或 HTTPS 入口完全不可访问，应通过 SSH 重启服务。

性能优化采用清单与实时指标分开存储：schema 22 保留目录、权限和硬件的原始采集时间，完整 API 通过只读视图合并；新版 Agent 仅在清单变化时重传正文，旧 Agent 仍可完整上报。数据库恢复导致缓存丢失时完整重试，不丢弃离线队列或重建身份。页面快照缓存收到上报或管理变更后立即失效；没有变更时最长缓存 30 秒。总览完整快照每 10 秒刷新，历史曲线每 30 秒刷新，实时指标继续按秒更新；SSH 清单仅在需要它的页面每分钟读取。

连接池默认最多 4 条，空闲 60 秒回收；显式配置继续生效。可选的 PostgreSQL 32 MiB 缓冲池配置需要管理员确认专用实例后重启，见 仓库 `deploy/database/README.md`。平台“进程性能”仅统计对应进程及其服务，评估全平台占用时还需单独计入 PostgreSQL；网络计数为应用正文，不含 TLS/TCP 和数据库协议开销。
