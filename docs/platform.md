# 平台结构

EasyManage 由 Rust 控制端、Rust Agent、PostgreSQL、Agent 本地 SQLite 队列和 React 控制台组成。服务器 1 同时运行控制端和本机 Agent；服务器 2 运行 Agent，平台通过可信 SSH 清单进行普通用户部署。

| 部分 | 作用 |
| --- | --- |
| `server/` | HTTPS API、节点注册、指标持久化、健康检查和经管理员认证的运维操作。 |
| `agent/` | 定时采集可见的主机指标，断线时将报告保存在本地 SQLite 队列。 |
| `protocol/` | Server 与 Agent 共享的版本化数据结构。 |
| `web/` | 设备总览、用户、存储、网络、安全、代理、AI 工具与编程环境页面。 |
| `docs/` | VitePress 文档源文件，构建后由控制端在 `/guide/` 提供。 |

`/api/v1/nodes` 返回最近一次 Agent 上报的数据；`/api/v1/nodes/{node_id}/history` 返回该节点近 10 分钟的有限历史采样。页面会标出采集时间与历史快照；“未观测到”不等于系统中不存在。

Agent 管理中的「应急重启」提供强制重启平台及逐节点强制重启 Agent。首次验证可信目标的管理员 SSH 与 sudo 后，可复用平台加密保存的密码或私钥，无须反复输入；更换浏览器、授权过期或清除时重新验证。操作会立即结束所选服务的全部进程再启动，当前连接会中断。Full 系统服务即使离线或启动失败，也保留 root 配置。平台重启安排在独立的 systemd 任务中，页面收到接受提示后等待约 5 秒再刷新。请求和结果写入平台服务日志，不记录密码或私钥。详见[管理员凭据复用](./deployment.md#管理员凭据复用)。

数据库不可用时，HTTPS 页面、可信目标清单及应急重启接口仍可访问；监控接口返回 503。平台在后台重试数据库初始化，数据库恢复后自动加载原有采集设置，随后恢复监控。强制重启平台不会自动修复 PostgreSQL；需管理员核对数据库服务、磁盘空间和日志。如果平台进程或 HTTPS 入口完全不可访问，应通过 SSH 重启服务。

性能优化采用清单与实时指标分开存储：schema 22 保留目录、权限和硬件的原始采集时间，完整 API 通过只读视图合并；新版 Agent 仅在清单变化时重传正文，旧 Agent 仍可完整上报。数据库恢复导致缓存丢失时完整重试，不丢弃离线队列或重建身份。页面快照缓存收到上报或管理变更后立即失效；没有变更时最长缓存 30 秒。总览完整快照每 10 秒刷新，历史曲线每 30 秒刷新，实时指标继续按秒更新；SSH 清单仅在需要它的页面每分钟读取。

连接池默认最多 4 条，空闲 60 秒回收；显式配置继续生效。可选的 PostgreSQL 32 MiB 缓冲池配置需要管理员确认专用实例后重启，见 仓库 `deploy/database/README.md`。平台“进程性能”仅统计对应进程及其服务，评估全平台占用时还需单独计入 PostgreSQL；网络计数为应用正文，不含 TLS/TCP 和数据库协议开销。

## Global Network：代理节点分析

在 Global Network 选择平台本机的 Clash/Mihomo YAML，或上传不超过 1 MiB、256 节点的文件。导入只提取独立代理节点，不执行其中的规则、TUN、DNS、控制端口、脚本或订阅下载；锚点需先展开。链式代理及网络绑定标记为暂不支持。最多保存 8 份配置，全部默认加入后台检测队列；重复导入完全相同的内容会复用原配置。覆盖仅更新内容，保留显示名、初次记录的文件名及同名同地址节点的 ID 和历史；改名必须使用单独的“重命名”，并校验原名和配置版本。

选择单份配置后，可点击“删除配置”，输入完整配置名称确认。此操作永久删除平台保存的导入副本、关联节点、检测历史和 IP 评分，并取消该配置正在进行的检测或评分；其他配置继续运行。原 YAML 文件、实际代理服务和 Agent 均不修改。名称或版本发生变化时拒绝删除，需要刷新后重新确认；删除后重新导入会创建新的配置和节点身份。

平台按统一三分钟时间槽并发检测全部到期配置，页面只选择查看对象。新增或更新其他配置不会取消正在执行的配置；可单独暂停某份配置，不影响其他配置。IP 评分仍只由用户手动触发。

点击“显示所有配置所有节点”可合并查看全部导入配置，统一筛选、排序，并显示所属配置。汇总视图默认关闭地区分组，仍可手动开启；下拉框可返回单份配置。它只读取已保存的检测结果，不启动额外探测；各节点的时间窗口和评分按所属配置保留。

地区分组默认开启，美国、日本、新加坡、台湾单独展示，其余地区默认折叠。关闭“地区分组”后，当前配置的全部地区节点合并为一个列表，可统一按名称、24 小时可用率或 IP 参考均分排序，筛选和已选节点保持不变。初始地区按名称推断，取得有效 IP 结果后标注已核验的出口地区。每个节点经独立 Mihomo 访问 Google、YouTube、Cloudflare、Microsoft、Apple、Bing、GitHub、Mozilla、Wikipedia、Amazon 共 10 个主流来源，兼顾受限网站与通用互联网。正常情况每站一次 HTTPS HEAD（不下载正文），8 秒超时，核验 TLS 与预期 HTTP 状态，不跟随重定向。达到 80% 即通过，即 10 站至少 8 站成功；以成功站点延迟中位数区分正常（≤ 1500 ms）和缓慢（> 1500 ms）。失败项均经原节点鉴权回环代理补充核验，传输错误最多退避重试一次；不把内核返回的 503/504 直接当成目标网站失败。限流、访问受限、网站服务异常和平台资源不足保留未确认，不计为成功，也不单凭这些证据判为节点故障。证书校验失败、重试后仍不通保留失败证据；最终状态依据逐站成功、失败、未确认是否足以确定至少 80% 的阈值。主列表逐站明细默认折叠，测试历史点击单轮后明细默认展开；节点 DNS 失败不会伪造逐站请求。域名按主机合并、错峰解析；系统 DNS 在 2.5 秒内未取得公网地址时，并行向 AliDNS / Cloudflare 发起 A 与 AAAA 加密 DNS 查询，任一来源返回匹配问题和 CNAME 链的有效公网地址即继续真实探测。DoH 验证 TLS、禁止环境代理及重定向；服务连接失败时使用固定服务地址重试，仍验证服务域名证书。成功的系统结果缓存 60 秒，加密结果遵守应答和 CNAME 最短 TTL、最多 5 分钟，失败仅缓存 15 秒；相同主机并发请求共享一次解析，最多保留 2048 个主机，不使用过期地址冒充可用。历史注明加密回退来源，并分别记录 NXDOMAIN、无 A/AAAA、SERVFAIL、解析超时及 HTTPS 服务错误。所有来源均未取得地址时保留未知，不将 DNS 故障当成远端节点故障。该判定不代表所有互联网网站都可用。

所有已启用配置按统一的三分钟时间槽检测。调度器用独立异步时钟启动新批次，不等待上一批完成；临时新增配置、慢探测和上一周期的回退均不能阻塞下一周期。按“配置 + 版本 + 时间槽”防止同一批重复派发；旧批次结束不会覆盖新批次进度。每个节点的网站探测有 100 秒独立期限，超时写入未确认记录，并保留已经取得的节点端口结果及仍有效的限流冷却信息。页面分别展示已完成、已保存、超时数量和下次检查时间；只有数据库确认写入的节点才计入已保存。平台对全部到期配置、全部节点和十个网站异步检测，不再采用 8 节点 / 16 请求的固定并发上限，也不再串行等待配置。域名解析按主机名合并，大批量节点在前 50 秒内分散启动，逐站启动另错开 100 毫秒，同一配置中仅显示名不同、凭据与协议参数完全相同的别名共享本轮真实探测，但每个别名分别保存结果和历史，并合并遵守已有冷却时间；不会把不同凭据或协议的节点合并。单节点最多同时请求 3 个网站，避免同一出口被瞬时连接挤占；节点间没有全局并发队列，各节点仍在本三分钟周期内完成。正常情况下整批共用一个临时 Mihomo 内核；内核启动失败则按配置并行隔离重试，避免单份配置阻断其他配置。临时内核使用 8 个 Go 调度线程、512 MiB 软 GC 目标，结束后退出释放资源；这些不是对平台或 Agent 的永久资源预留。用户级平台服务的内存硬上限为 4 GiB、任务上限 512、文件描述符软 / 硬上限 65536，避免 systemd 默认 1024 软上限截断并发连接；包含平台启动的临时内核；Agent 仍使用独立的低资源设置。每站有 8 秒超时，正常检测不重复发起外部网站请求；限流 / 访问受限时按下述规则补充核验和回退。本地 Unix 控制连接尚未建立时，可在 4 秒内退避重连，连接成功发出的外部请求不会重复执行。每轮显示真实开始 / 结束时间、耗时以及完成 / 总节点数；网络故障也会保存失败样本，内核证据不足保存未知样本。停机、数据库异常和导入前的历史保持灰色，不补造观测。

内核返回失败、超时、证据不足或非预期 HTTP 状态时，平台使用该节点自己的鉴权回环代理读取真实状态码与 `Retry-After`；不会切换实际代理，不会通过 DIRECT 获取网站结果。收到 429 或带 Retry-After 的 403 / 503 时明确保留限流证据；收到限制、重定向或网站错误页可尝试一次同服务备用地址，成功仍只算该服务的一票，不增加分母。不能确认时保留未知，不能把错误页计为访问成功。主地址和备用地址均验证服务器证书；传输错误仅退避复核一次，平台资源错误与证书错误不重复施压。
主地址与备用地址分别遵守 Retry-After（秒数或 HTTP 日期）；429 没有该头时默认冷却 60 秒。冷却时间随该节点的轮次结果保存在 PostgreSQL，后续轮次和平台重启均会加载；冷却期间不重复请求对应地址。原地址和备用地址均被限流时保留“限流 / 未确认”，不能作为节点故障证据。前端展开站点明细可看到原状态码、备用域名、备用状态码与冷却时间。平台不保存响应正文、Cookie 或原始响应头，也不处理验证码。


图表可切换“HTTPS 访问真实网站”和“平台与节点连接”，切换仅使用已保存的数据。后一种记录平台直接连接节点原地址和配置端口的 TCP 握手耗时（5 秒超时），不经过代理访问网站、不要求目标向平台反向发起请求、不依赖 SSH 或 Agent。UDP 专用协议明确标为暂不支持 TCP 检测，不把 TCP 不通当成 UDP 故障。两类历史、可用率、延迟和覆盖率独立计算；旧记录没有节点连接数据，保持未采集。

新网站判定采用规则版本 5，仅验证 HTTPS 响应头，不测试账号登录或视频播放。至少 80% 即通过（10 站至少 8 站）；网站在不同网络的限制可能不同。旧版通用互联网和规则 3 的受限网站及规则 4 的严格超过 80% 检测保留原来源表及原判定，不回写旧历史；版本 4/5 使用相同来源并沿用有效冷却；来源目录改变的旧版本不混用冷却证据。精简 JSON 在原有轮次内追加节点连接摘要，不保存重复 URL 或响应正文，不增加数据库表。

24 小时窗口含 480 个真实采样槽，前端每 5 个槽聚合为一格。竖条加高，大格背景保留 15 分钟的汇总色，内部从上到下紧贴堆叠 5 条横向小格，无间距，分别显示每次 3 分钟检测的状态；悬停可查看逐次时间和结果。多站通过且成功站点延迟中位数 ≤ 1500 ms 为绿色正常，通过且中位数 > 1500 ms 为黄色缓慢，已确认的失败足以确定成功比例低于 80% 或节点连接复核失败为红色不可用；DNS 无法确认、未采集、不支持或内核异常为灰色未知。15 分钟大格若有缓慢或成功 / 失败混合，也显示黄色；条纹表示该格观测不完整。可用率仅以有效检测为分母，旁边另列覆盖率。暂停、平台离线、内核故障和未采集的历史不会补成正常或节点故障。数据库按轮保存精简 JSON，不保存逐请求正文；可用性记录保留 7 天，IP 分数每来源仅保存最近一次。

Global Network 提供「七天测试历史」入口，每个节点也可打开「测试历史」。独立页面不挂载实时监控或 Agent 轮询；默认显示七天，每行 24 小时，支持切换 24 小时视图及 HTTPS / 节点端口视图，按需重新读取，不自动刷新或触发探测。最早尚未采集或已过期的时段保持灰色。

历史明细直接从现有 `proxy_lab_rounds.results` 读取，保留当时的规则版本、配置版本、检测时间、逐站验证耗时、失败原因、限流冷却及节点端口证据；按时间游标分页，每页默认 50 轮、上限 100，不复制一份文本日志或网站正文。七天概览在 PostgreSQL 内提取单个节点，避免把七天全配置 JSON 搬入平台内存；同时最多两个按需历史查询。原 24 小时监控接口仍只读取 480 个时间槽。正常成功的补充反馈和空元数据不再重复保存，成功来源仍保留经验证的耗时。每次平台启动和每 15 分钟自动清理七天前的测试轮次，读接口始终限制七天范围。沿用原表及 `(profile_id, slot)` 索引，不新增历史日志表或迁移已有结果；旧规则不会回算成新规则，七天记录从实际存留的数据逐步积累。

节点卡片的机构评分默认折叠，点击“展开评分”后查看。IP 评分只由用户点击执行，每批最多 16 节点。八个来源全部列出，其中当前已验证的公开 API 为 [IPPure](https://ippure.com/MyIP-Info-API)、[IPure.dev](https://ipure.dev/docs/api) 和 [IPOK](https://ipok.io/developers)；其余来源提供原站核验和人工录入。需要验证码、限流、缺乏有效分值时保留原因，不绕过验证，不把未知当零分。人工录入会单独标注。各来源保留原始分值、分值方向、查询时间和出口 IP；纯净度统一为高分更好。参考均分只计同一出口 IP、当前配置、24 小时内的有效结果，不能理解为独立机构的官方综合评级。

节点凭据通过独立 AES-256-GCM 密钥加密保存在 PostgreSQL，不返回 YAML 正文、代理密码或 UUID。状态目录默认是 `~/.easymanage/config/proxy-lab/`（0700），密钥 0600；可用 `EASYMANAGE_PROXY_LAB_STATE_DIR` 指定。数据库备份之外须保留原密钥。安装独立内核见仓库 `deploy/third-party/README.md`。全部检测在平台运行，Agent 不增加采集、请求或依赖，原有代理配置和服务不重载。

无 HOME 的系统服务默认使用 `/var/lib/easymanage-server/proxy-lab`，管理员需为服务提供可写的私有状态目录与可信内核路径；未启用分析时不会创建密钥或探测。临时内核配置为 0600，正常结束删除；残留超过 15 分钟的工作目录会被定期清理。

在 Global Network 的「检测范围」选择「本机网络检测」，列表切换为国内 20 个预设网站，支持网站名 / 域名筛选、按可用率和耗时排序及独立七天历史。检测在平台层每三分钟按独立时钟异步启动，使用禁用环境代理的 HTTPS HEAD 客户端，经本机系统路由直连；不调用 Mihomo、SSH 或 Agent，也不读取响应正文或跟随重定向。优先 HEAD，返回 404 / 405 / 501 时额外执行一次 GET 兼容复核，不主动读取或保存正文、不跟随重定向。每次请求最多 8 秒，单站总预算 18 秒，HEAD 网络错误最多重试一次，GET 不重试，403 / 429 不触发兼容请求；四个网站并行，单轮预算 110 秒，慢批次不阻止下一周期。新记录保留 HEAD 原始状态和 GET 真实状态；GET 失败时保留已验证的 HEAD 可达证据与复核失败原因。

本机视图测量 DNS、连接、TLS 和响应头耗时。收到证书有效的 HTTPS / HTTP 响应即可证明本机到目标的网络可达；403 / 429 等另标「网站访问受限」，5xx 另标「网站服务异常」，不冒充网站业务成功，也不将应用限制直接解释为本机断网。超时、连接或证书验证失败记录真实失败；本机资源不足记录未知。指标阈值沿用 1500 ms 区分正常与缓慢。预设来源为百度、腾讯网、微信、淘宝、天猫、京东、拼多多、哔哩哔哩、抖音、快手、微博、知乎、网易、新浪、搜狐、360 搜索、央视网、新华网、人民网和中国政府网。

本机结果写入 `local_network_rounds`，每轮仅一行，保存网站稳定 ID、状态、耗时和 HTTP 状态，不重复保存站点目录、正文或文本日志；七天过期清理与已有代理检测共用维护任务。网页刷新只读已保存结果，不触发额外请求。本机网络不占 YAML 配置名额，也不继承代理节点的 IP 评分或地区分组。单站历史仍按需查询、每页最多 100 轮日志，不自动轮询七天数据。

本机网络检测默认开启。可在平台环境配置中设置 `EASYMANAGE_LOCAL_NETWORK_ENABLED=false` 并重启平台以停止新增检测；现有七天历史仍可读取。

Global Network 检测区提供「本配置检测 / 本机网站检测」与「所有检测」开关。单项开关立即保存；总开关的开启、关闭均需确认弹窗，接口也验证确认标记和配置版本。总开关关闭时取消正在执行的 YAML、节点端口、本机网站检测及手动 IP 评分，不再启动新检测；配置、每项选择及七天历史保留。重新打开总开关按原单项选择恢复，IP 评分仍需手动操作，不补造暂停时段记录。开关保存在 PostgreSQL，重启仍有效。本机来源受平台环境 `EASYMANAGE_LOCAL_NETWORK_ENABLED` 的上限约束。所有开关仅影响平台层网络检测，不停止 Agent 的其他采集。

YAML 导入的覆盖目标按输入的「显示名称」精确匹配，忽略输入两端空白；只有唯一同名配置才显示覆盖勾选，不以当前查看的配置作为默认覆盖目标。不同名按新配置导入，同名必须明确确认覆盖；切换文件、来源、名称或目标版本时清除覆盖勾选。后端在写锁内再次核验同名与原版本。内容完全相同但异名的重复导入仅复用已有配置，不改变原名称、检测开关和历史。
